# Git Commit Message Generation Rules

## Format: Conventional Commits

Use the Conventional Commits specification for all commit messages.

### Commit Message Structure:

```
<type>(<scope>): <subject>

<body>

[BREAKING CHANGE: <description>]
```

### Types (Feature & Architecture Oriented):
- **feat**: New feature or functionality
- **arch**: Architecture changes (layers, patterns, structure)
- **refactor**: Code refactoring without changing behavior
- **perf**: Performance improvements
- **test**: Adding or updating tests
- **fix**: Bug fixes
- **docs**: Documentation changes
- **build**: Build system or dependency changes
- **ci**: CI/CD changes
- **style**: Code style/formatting (no logic changes)

### Scope Examples:
- Component names: `(builder)`, `(executor)`, `(adapter)`
- Layer names: `(core)`, `(tests)`, `(harness)`
- Feature areas: `(lifecycle)`, `(validation)`, `(integration)`

### Subject Line Rules:
- Use imperative mood ("add feature" not "added feature")
- No period at the end
- Maximum 72 characters
- Lowercase after the colon

### Body Format (Summary + Bullet Points):

**Required:**
- Brief summary of what changed and why
- Bullet points listing key changes
- Each bullet should describe one significant change

**Example:**
```
feat(adapter): add comprehensive TestInstance validation

Added parameter validation and property tests for TestInstance
to ensure data integrity throughout the framework.

Changes:
- Created TestInstance_Tests.cs with 41 test cases
- Added null parameter validation tests
- Added property immutability tests
- Added real-world usage pattern tests
- Verified constructor parameter handling
```

### Breaking Changes:

When changes break backward compatibility:

1. Add `BREAKING CHANGE:` footer
2. Explain what breaks
3. Explain migration path

**Example:**
```
arch(core): restructure test lifecycle execution order

Refactored the test lifecycle to execute in a more predictable
order, improving test isolation and reliability.

Changes:
- Modified SetupOnce to run before all child contexts
- Changed TeardownOnce to run after all child contexts
- Updated execution order documentation

BREAKING CHANGE: Test lifecycle execution order has changed.
Tests that relied on the previous execution order may need
updates. See migration guide in docs/migration.md for details.
```

### Additional Guidelines:

1. **Be Specific**: Focus on what changed at the architecture/feature level
2. **Explain Why**: Include motivation for non-obvious changes
3. **Reference Tests**: Mention test coverage when relevant
4. **Keep Concise**: Aim for 3-7 bullet points maximum
5. **Technical Detail**: Include technical details in bullets, not just "updated X"

### Anti-Patterns to Avoid:

❌ Vague: `fix: fixed stuff`
✅ Specific: `fix(executor): correct lifecycle phase ordering`

❌ Too generic: `refactor: improved code`
✅ Specific: `refactor(builder): extract action collection logic into helper`

❌ Missing context: `test: add tests`
✅ With context: `test(adapter): add 27 tests for TestContextAdapter lifecycle`

❌ No bullets: Just a summary
✅ With bullets: Summary + detailed change list

### Example Commit Messages:

**Feature:**
```
feat(core): implement async lifecycle support

Added support for async actions in all lifecycle phases,
enabling async setup/teardown operations.

Changes:
- Modified ContextualTestCaseBuilder to accept Func<Task>
- Added async-to-sync conversion via GetAwaiter().GetResult()
- Updated all lifecycle phases (Setup/Act/Teardown)
- Added 15 async operation tests
- Updated documentation with async examples
```

**Architecture:**
```
arch(adapters): introduce TestContextAdapter abstraction

Implemented adapter pattern to decouple test case model from
execution, improving testability and maintainability.

Changes:
- Created ITestContextAdapter interface
- Implemented TestContextAdapter wrapping lifecycle actions
- Added 27 comprehensive adapter tests
- Updated TestCaseExecutor to use adapter
- Improved separation of concerns between layers
```

**Test:**
```
test(validation): add parameter validation coverage

Added comprehensive tests for OrThrowIfParameterIsNull
extension method used throughout the framework.

Changes:
- Created ExceptionExtensions_Tests with 19 test cases
- Tested null reference type throwing
- Tested non-null passthrough behavior
- Tested value types and framework types
- Verified error message formatting
```

**Breaking Change:**
```
arch(lifecycle): change parent-child action inheritance order

Modified action collection to use consistent top-down for setup
and bottom-up for teardown, improving predictability.

Changes:
- SetupOnce/SetupEach now collect parent → child (top-down)
- TeardownEach/TeardownOnce now collect child → parent (bottom-up)
- Updated all 2,900+ lines of lifecycle tests
- Added documentation explaining new order
- Verified against real-world test scenarios

BREAKING CHANGE: Child contexts now inherit parent setup actions
in reversed order. Tests relying on specific inheritance order
must be updated. Parent actions run before child actions for
Setup phases, child actions run before parent actions for
Teardown phases.
